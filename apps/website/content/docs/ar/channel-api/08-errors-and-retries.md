# الأخطاء وإعادة المحاولة

## بنية الخطأ

```json
{
  "error": {
    "code": "NOT_AVAILABLE",
    "message": "Not enough free cabins",
    "details": {}
  }
}
```

اعتمد في منطق التطبيق على `code`، وليس على نص `message`.

## رموز الأخطاء

| HTTP  | الرموز والمعنى                                                                                                                                                         |
| ----- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `400` | `VALIDATION_FAILED`: الطلب لا يطابق المواصفة التقنية، بما يشمل إرسال حقول غير معروفة.                                                                                  |
| `401` | `UNAUTHENTICATED`: احصل على رمز وصول جديد.                                                                                                                             |
| `403` | `CONTRACT_FORBIDS`، `FORBIDDEN`.                                                                                                                                       |
| `404` | `NOT_FOUND`؛ ويُستخدم أيضًا عند محاولة الوصول إلى حجز أو حجز مؤقت تابع لقناة أخرى.                                                                                     |
| `409` | `NOT_AVAILABLE`، `STOP_SALE`، `SAILING_CLOSED`، `HOLD_EXPIRED`، `HOLD_NOT_ACTIVE`، `QUOTE_EXPIRED`، `REVISION_CHANGED`، `INVALID_STATE`، `RETRY_LATER`، `IN_PROGRESS`. |
| `422` | `INVALID_OCCUPANCY`، `NO_RATE_FOR_SEASON`، `IDEMPOTENCY_KEY_REUSED`.                                                                                                   |
| `429` | `RATE_LIMITED`.                                                                                                                                                        |
| `503` | `SERVICE_UNAVAILABLE`.                                                                                                                                                 |

## مفاتيح منع تكرار التنفيذ

يتطلب كل طلب `POST` أو `PATCH` أو `DELETE` الترويسة:

```http
Idempotency-Key: <uuid>
```

استخدم UUID جديدًا لكل عملية مستقلة، واحتفظ بالقيمة نفسها عند إعادة محاولة العملية ذاتها.

يحتفظ ريفرديسك بالمفاتيح لمدة ٧ أيام، ويعيد النتيجة الأصلية عند تكرار الطلب بالمفتاح نفسه.

## الإجراء المناسب لكل حالة

| الحالة                                                 | ما يجب فعله                                                                                                                                                     |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| انتهاء مهلة الاتصال أو حدوث خطأ شبكة أثناء عملية كتابة | أعد المحاولة بالمفتاح نفسه للحصول على النتيجة الأصلية دون إنشاء حجز إضافي.                                                                                      |
| `409 IN_PROGRESS`                                      | العملية الأولى ما زالت قيد التنفيذ. انتظر المدة المحدّدة في `Retry-After`، ثم أعد المحاولة بالمفتاح نفسه.                                                       |
| `422 IDEMPOTENCY_KEY_REUSED`                           | أُعيد استخدام المفتاح مع محتوى مختلف. صحّح منطق التطبيق، وخصّص مفتاحًا جديدًا لكل عملية مستقلة.                                                                 |
| إعادة المحاولة بعد أكثر من ٧ أيام                      | أعد التأكيد أو إرسال طلب الحجز باستخدام `channel_ref` نفسه؛ ليُعاد الحجز الموجود.                                                                               |
| `409 RETRY_LATER`                                      | يوجد ضغط على النظام. أعد المحاولة بعد المدة المحدّدة في `Retry-After`.                                                                                          |
| `429 RATE_LIMITED`                                     | انتظر عدد الثواني المحدّد في `Retry-After` قبل المتابعة.                                                                                                        |
| `503 SERVICE_UNAVAILABLE`                              | يتعذّر على ريفرديسك الوصول إلى قاعدة البيانات. اعرض الرحلات باعتبارها رهن الطلب، وأعد المحاولة بعد المدة المحدّدة في `Retry-After`، وهي ٣٠ ثانية في هذه الحالة. |
