# نظرة عامة

تتيح الواجهة للشركات والمنصات الإلكترونية بيع كبائن شركات المراكب النيلية مباشرة من أنظمتها، اعتمادًا على بيانات محدّثة لحظة بلحظة.

تقتصر العمليات المتاحة لكل قناة على ما يسمح به عقدها مع شركة المراكب النيلية. وهذا الدليل موجّه إلى المطوّرين المسؤولين عن تنفيذ الربط.

## أساسيات الاتصال

- تعتمد الواجهة على REST عبر HTTPS، وتستخدم JSON في الطلبات والاستجابات.
- تستخدم المصادقة OAuth 2.0 بأسلوب `client_credentials`، للحصول على رمز وصول قصير الصلاحية. راجع [المصادقة](/docs/channel-api/authentication).
- تتوفر المواصفة التقنية بصيغة OpenAPI 3.1 على المسار `/openapi.yaml`، والمرجع التفاعلي على `/docs` في خادم الواجهة.
- تُمثَّل المبالغ بأعداد صحيحة بوحدات العملة الصغرى، مع رمز العملة.
- تُحدَّد الأسواق برموز مثل `international` أو `gcc`. لكل شركة مراكب نيلية قائمتها الخاصة؛ اطلب منها الأسواق المسموح بها في عقدك.
- تُكتب تواريخ الرحلات بصيغة `YYYY-MM-DD`، وفق تاريخ القاهرة. وتُكتب الأوقات بصيغة ISO 8601 مع تحديد المنطقة الزمنية.

## عن الأمثلة في هذا الدليل

في الأمثلة، يشير `$API` إلى العنوان الأساسي لخادم الواجهة، ويشير `$H` إلى ترويسة المصادقة `Authorization: Bearer <token>`. أما المتغيّرات الأخرى فتُستبدل بالقيم الناتجة من الخطوات السابقة.

> [!NOTE]
> أمثلة `uuidgen` تنشئ مفتاحًا لعملية جديدة. **عند إعادة محاولة العملية نفسها، استخدم المفتاح السابق نفسه.**

## تمثيل المبالغ المالية

يمثّل المثال التالي مبلغ ١٬١٧٠٫٠٠ دولارًا أمريكيًا:

```json
{ "amount": 117000, "currency": "USD" }
```

وللدينار الكويتي والدينار البحريني والريال العُماني ثلاث منازل عشرية. لذلك يمثّل المثال التالي ١٫٢٥٠ دينار كويتي:

```json
{ "amount": 1250, "currency": "KWD" }
```

## عميل مستقل لكل شركة مراكب نيلية

تُسجَّل منصتك كقناة بيع لدى كل شركة مراكب نيلية تتعامل معها، وتحصل على عميل واجهة برمجة تطبيقات مستقل لكل شركة.

يتيح رمز الوصول الصادر عن هذا العميل الوصول إلى بيانات تلك الشركة فقط، وفي حدود المراكب وفئات الكبائن وخطط الأسعار والشروط المحدّدة في عقدك.

## تسلسل إنشاء الحجز

| الخطوة               | الطلب                         | الغرض                                              |
| -------------------- | ----------------------------- | -------------------------------------------------- |
| معرفة ما يُسمح ببيعه | `GET /v1/vessels`             | قراءة المراكب وفئات الكبائن المتاحة ضمن العقد      |
| الاستعلام عن الإتاحة | `GET /v1/availability`        | معرفة الكبائن المتاحة لكل موعد إبحار وفئة          |
| تسعير الاختيار       | `POST /v1/quotes`             | احتساب سعر الرحلة والكبائن والضيوف                 |
| الاحتفاظ بالكبائن    | `POST /v1/holds`              | حجز الكبائن مؤقتًا أثناء إتمام العميل لخطوات الحجز |
| تأكيد الحجز          | `POST /v1/holds/{id}/confirm` | إرسال بيانات الضيوف وتحويل الحجز المؤقت إلى حجز    |
| قراءة الحجز          | `GET /v1/bookings/{ref}`      | متابعة تفاصيل الحجز وحالته ونسخته الحالية          |

في عقود «الحجز عند الطلب»، ترسل طلب حجز بدلًا من إنشاء حجز مؤقت. راجع [الطلبات والعروض البديلة](/docs/channel-api/requests-and-offers).

ويُبلغك ريفرديسك بالتغييرات من خلال إشعارات أحداث موقّعة.

## ضمانات التشغيل

- **الحجز ضمن السعة المتاحة:** يُحجز الاختيار على جميع مراحل الرحلة. وتظل الكبائن محفوظة لقناتك حتى انتهاء الحجز المؤقت أو تحريره.
- **إعادة المحاولة دون تكرار التنفيذ:** تستخدم عمليات الكتابة الترويسة `Idempotency-Key`. وعند تكرار العملية بالمفتاح نفسه، تُعاد النتيجة الأصلية. راجع [الأخطاء وإعادة المحاولة](/docs/channel-api/errors-and-retries).
- **حماية بيانات الضيوف:** تقبل الواجهة أرقام جوازات السفر وتواريخ الميلاد، لكنها لا تعيدها في الاستجابات أو الأحداث أو الإشعارات.
