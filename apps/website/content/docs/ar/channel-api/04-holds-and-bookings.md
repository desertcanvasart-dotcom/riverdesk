# الحجوزات المؤقتة وتأكيد الحجوزات

## إنشاء حجز مؤقت

```bash
curl -s -X POST "$API/v1/holds" \
  -H "$H" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H 'Content-Type: application/json' \
  -d '{
    "quote_id": "'$QUOTE'",
    "kind": "checkout"
  }'
```

| قيمة `kind` | الاستخدام                                           | المدة الافتراضية في العقد |
| ----------- | --------------------------------------------------- | ------------------------- |
| `checkout`  | إتمام العميل للدفع على موقعك                        | ٣٠ دقيقة                  |
| `option`    | الاحتفاظ بالكبائن للشركة ريثما يؤكّد العميل اختياره | ٧٢ ساعة                   |

تُحجز الكبائن على جميع مراحل الرحلة حتى الموعد المحدّد في `expires_at`.

إذا لم تتوفر سعة كافية، يفشل الطلب بالرمز `NOT_AVAILABLE`.

لتحرير حجز مؤقت قبل انتهاء مهلته، استخدم:

```http
DELETE /v1/holds/{id}
```

أما الحجوزات المؤقتة المنتهية، فتُحرَّر تلقائيًا، ويصلك الحدث `hold.expired`.

## تأكيد الحجز

```bash
curl -s -X POST "$API/v1/holds/$HOLD/confirm" \
  -H "$H" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H 'Content-Type: application/json' \
  -d '{
    "channel_ref": "NC-50211",
    "guests": [
      {
        "cabin": 0,
        "first_name": "Emma",
        "last_name": "Clarke",
        "lead": true,
        "nationality": "GB"
      }
    ]
  }'
```

راعِ القواعد التالية:

- `channel_ref` هو رقم الحجز في نظامك. يظل فريدًا داخل قناة البيع؛ وإعادة التأكيد بالقيمة نفسها تعيد الحجز الموجود، وهو ما يساعد على استعادة النتيجة بعد انقطاع طويل.
- يجب تحديد ضيف رئيسي واحد فقط باستخدام `lead`.
- يشير `cabin` إلى ترتيب الكابينة داخل عرض السعر، ويبدأ من ٠.
- تقبل الواجهة `passport_number` و`date_of_birth`، وتحفظهما مشفّرين دون إعادتهما في الاستجابات.

تعيد الاستجابة الحجز ورقمه المرجعي، مثل `VS-26-00611`، وحالته:

| الحالة      | المعنى                                                                                                                                |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `confirmed` | تم تأكيد الحجز.                                                                                                                       |
| `requested` | يعمل العقد بالآجل، لكن القناة تجاوزت حد الائتمان. يظهر السبب `reason: "credit_limit"`، ويحتاج الحجز إلى قرار من شركة المراكب النيلية. |

## قراءة الحجز

```bash
curl -si "$API/v1/bookings/$REF" -H "$H"
```

تتضمن الاستجابة موعد الإبحار ومراحله، والكبائن وأسماء الضيوف، والإجماليات، والمدفوعات المستحقة، ورقم نسخة الحجز الحالية `revision`.

تظهر قيمة النسخة أيضًا في ترويسة `ETag`، وتُستخدم عند تطبيق تعديل على الحجز.

يمكنك قراءة حجوزات قناتك فقط. ويُعاد الرمز `404` عند محاولة قراءة حجز تابع لقناة أخرى.
