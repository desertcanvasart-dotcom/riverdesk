# الطلبات والعروض البديلة

إذا كانت الإمكانية تعرض `status: "on_request"`، فإن عقدك يعمل بنظام «الحجز عند الطلب».

ترسل قناتك الطلب، وتقرّر شركة المراكب النيلية قبوله أو رفضه. ولا تُحجز كبائن للطلب قبل الموافقة عليه.

## إرسال طلب حجز

```bash
curl -s -X POST "$API/v1/requests" \
  -H "$H" \
  -H "Idempotency-Key: $(uuidgen)" \
  -H 'Content-Type: application/json' \
  -d '{
    "quote_id": "'$QUOTE'",
    "channel_ref": "NC-REQ-1",
    "guests": [
      {
        "cabin": 0,
        "first_name": "Ana",
        "last_name": "Lopez",
        "lead": true
      }
    ]
  }'
```

تعيد الاستجابة الحجز بالقيمة `status: "requested"`، مع الحقل `request_expires_at` الذي يحدّد موعد انتهاء الطلب.

تُؤخذ المهلة من العقد، وتكون افتراضيًا ٦ ساعات، تضاف إليها مهلة إضافية قصيرة.

## استلام القرار

يصل القرار من خلال الحدث `request.decided`، وتوضّحه قيمة `data.decision`:

| القرار           | المعنى                               |
| ---------------- | ------------------------------------ |
| `accepted`       | قُبل الطلب وأُكّد الحجز.             |
| `declined`       | رُفض الطلب، ويظهر السبب في الحجز.    |
| `timed_out`      | انتهت المهلة دون رد.                 |
| `offer_accepted` | قبلت قناتك عرضًا بديلًا.             |
| `offer_expired`  | انتهت صلاحية العرض البديل دون قبوله. |

## العروض البديلة

قد تقترح الشركة موعد إبحار آخر بدلًا من المطلوب.

يصلك الحدث `offer.created` متضمنًا:

- `offer_id`: معرّف العرض.
- `sailing_id`: معرّف موعد الإبحار البديل.
- `expires_at`: موعد انتهاء العرض، ومدته الافتراضية ٤٨ ساعة.

يظهر العرض المفتوح وسعره ضمن بيانات الحجز.

لقبول العرض:

```bash
curl -s -X POST "$API/v1/offers/$OFFER/accept" \
  -H "$H" \
  -H "Idempotency-Key: $(uuidgen)"
```

إذا لم تقبل العرض خلال المهلة، تنتهي صلاحيته تلقائيًا.
